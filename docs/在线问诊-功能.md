# 在线问诊 - 功能接口文档

## 功能概述

在线问诊模块提供患者与医生之间基于文字聊天的远程医疗服务，支持问诊发起、实时消息收发、处方开具与查看。采用 AJAX 轮询机制实现消息实时同步（3秒间隔）。

---

## 数据模型关系

```
consultation (问诊记录)
  ├── 1:N → consultation_message (消息，含处方卡片)
  └── 1:N → prescription (处方)
              └── 1:N → prescription_item (明细 → medicine)
```

---

## 接口列表

### 1. 发起问诊

**接口地址**: `POST /api/consultations/create`

**认证**: JWT（患者角色）

**请求体**:
```json
{
  "doctorId": 1,
  "deptId": 1,
  "type": "TEXT",
  "symptomDescription": "最近三天持续头痛，伴有轻微恶心..."
}
```

**返回数据**:
```json
{
  "code": 200,
  "message": "问诊发起成功",
  "data": {
    "id": 1,
    "consultationNo": "CONS20260519143025001",
    "patientId": 3,
    "patientName": "患者",
    "doctorId": 1,
    "doctorName": "张伟",
    "doctorTitle": "主任医师",
    "deptId": 1,
    "deptName": "内科",
    "type": "TEXT",
    "typeText": "文字问诊",
    "status": 0,
    "statusText": "待接诊",
    "symptomDescription": "最近三天持续头痛...",
    "createdAt": "2026-05-19T14:30:25"
  }
}
```

### 2. 发送消息

**接口地址**: `POST /api/consultations/{id}/message`

**认证**: JWT

**路径参数**:
- `id`: 问诊ID

**请求体**:
```json
{
  "content": "医生您好，我的头痛主要在太阳穴位置...",
  "messageType": "TEXT"
}
```

**返回数据**:
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "id": 5,
    "senderId": 3,
    "senderType": "PATIENT",
    "senderName": "患者",
    "messageType": "TEXT",
    "content": "医生您好，我的头痛主要在太阳穴位置...",
    "time": "14:32",
    "createdAt": "2026-05-19T14:32:10"
  }
}
```

**业务规则**:
- 医生首次回复时，问诊状态自动从"待接诊(0)"变为"问诊中(1)"
- 患者消息不改变问诊状态
- 系统自动插入系统消息（问诊发起、医生接诊、问诊结束）

### 4. 获取我的问诊列表（分页）

**接口地址**: `GET /api/consultations/my-list`

**认证**: JWT

**请求参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| userType | String | 是 | PATIENT（患者视角）或 DOCTOR（医生视角） |
| status | String | 否 | 状态筛选：0-待接诊, 1-问诊中, 2-已完成, 3-已关闭 |
| pageNum | Integer | 否 | 页码，默认1 |
| pageSize | Integer | 否 | 每页数量，默认10 |

**返回数据**:
```json
{
  "code": 200,
  "data": {
    "total": 8,
    "pageNum": 1,
    "pageSize": 10,
    "list": [
      {
        "id": 1,

        "doctorName": "张伟",
        "doctorTitle": "主任医师",
        "deptName": "内科",
        "type": "TEXT",

        "symptomDescription": "最近三天持续头痛...",
        "createdAt": "2026-05-19T14:30:25"
```

### 5. AJAX轮询获取新消息

**接口地址**: `GET /api/consultations/{id}/messages`

**认证**: JWT

**请求参数**:
| 参数 | 类型 | 说明 |
|------|------|------|
| afterMessageId | Long | 上次收到的最后一条消息ID，只返回比它大的新消息 |

**返回数据**:
```json
{
  "code": 200,
  "data": [
    {
      "id": 4,
      "senderType": "DOCTOR",
      "senderName": "张伟",
      "messageType": "TEXT",
      "content": "根据你的描述，可能是紧张性头痛...",
      "time": "14:35"
    }
  ]
}
```

**前端使用方式**:
- 进入聊天界面后启动 `setInterval(refreshMessages, 3000)`（3秒轮询）
- 每次轮询传入 `lastMessageId`，只获取增量消息
- 新消息通过 `insertAdjacentHTML('beforeend', html)` 追加到聊天区域

### 6. 医生接诊

**接口地址**: `POST /api/consultations/{id}/accept`

**认证**: JWT（医生角色）

**返回数据**:
```json
{
  "code": 200,
  "message": "已接诊",
  "data": null
}
```

**业务规则**:
- 仅"待接诊(0)"状态可接诊
- 接诊后状态变为"问诊中(1)"，自动插入系统消息"医生已接诊"

---

### 7. 结束问诊

**接口地址**: `POST /api/consultations/{id}/finish`

**认证**: JWT

**返回数据**:
```json
{
  "code": 200,
  "message": "问诊已结束",
  "data": null
}
```

**业务规则**:
- 结束后状态变为"已完成(2)"，自动插入系统消息"本次问诊已结束"

---

## 状态枚举

### 问诊状态 (consultation.status)

| 状态码 | 状态名称 | 说明 |
|--------|----------|------|
| 0 | 待接诊 | 患者已发起，等待医生响应 |
| 1 | 问诊中 | 医生已接诊，双方可聊天 |
| 2 | 已完成 | 问诊正常结束 |
| 3 | 已关闭 | 问诊被关闭 |

### 处方状态 (prescription.status)

| 状态码 | 状态名称 | 说明 |
|--------|----------|------|
| 0 | 待审核 | 处方待药师审核 |
| 1 | 已生效 | 处方可直接使用 |
| 2 | 已作废 | 处方已作废 |

### 消息发送者类型 (senderType)

| 值 | 说明 |
|------|------|
| PATIENT | 患者发送的消息 |
| DOCTOR | 医生发送的消息 |
| SYSTEM | 系统自动消息（接诊/结束提示） |

### 消息类型 (messageType)

| 值 | 说明 |
|------|------|
| TEXT | 普通文字消息 |
| IMAGE | 图片消息（预留） |
| PRESCRIPTION | 处方卡片消息（可点击查看详情） |

### 问诊类型

| 值 | 说明 |
|------|------|
| TEXT | 文字问诊 |
| VIDEO | 视频问诊（施工中） |

## 错误码说明

| 错误码 | 说明 |
|--------|------|
| 200 | 操作成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或 Token 失效（"请先登录"） |
| 500 | 服务器内部错误或业务异常 |

### 常见业务异常

| 异常信息 | 触发条件 |
|----------|----------|
| "请先登录" | SecurityUtils.getCurrentUserId() 返回 null |
| "问诊记录不存在" | consultationId 查不到 |
| "问诊已结束" | 对已完成/已关闭的问诊发消息 |
| "无权发送消息" | 非问诊参与方试图发消息 |
| "当前状态无法接诊" | 对非待接诊状态的问诊执行接诊 |
| "医生信息不存在" | 开具处方时找不到对应 doctor |
| "处方不存在" | prescriptionId 查不到 |

## 前端交互设计要点

### 聊天界面结构
```
┌──────────────────────────────┐
│  ← 返回  │ [头像] 张伟 主任医师 │ 问诊中 │  ← chat-header
├──────────────────────────────┤
│                              │
│     🔔 问诊已发起...         │  ← 系统消息（居中）
│                              │
│             ┌──────────────┐ │
│             │ 最近三天头痛  │ │  ← 我方消息（右对齐，蓝绿渐变）
│             └──────────────┘ │
│                              │
│  ┌──────────────────────┐    │
│  │ 可能是紧张性头痛...   │    │  ← 对方消息（左对齐，白色卡片）
│  └──────────────────────┘    │
│                              │
│  ┌ 💊 医生开具了处方 ────┐   │  ← 处方卡片（可点击）
│  └────────────────────────┘  │
│                              │
├──────────────────────────────┤
│ [输入消息...]           [发送] │  ← chat-footer
└──────────────────────────────┘
```

### 消息轮询机制
```
进入聊天 → startPolling() → setInterval(3000ms)
                                │
                                ▼
                          refreshMessages()
                                │
                          GET /messages?afterMessageId=lastId
                                │
                         有新消息？
                         ├─ 是 → insertAdjacentHTML 追加 → 更新 lastMessageId
                         └─ 否 → 不操作
离开聊天 → stopPolling() → clearInterval
```
